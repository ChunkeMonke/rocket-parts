# Rocket Build Planner

Shop constants, fits, print rules and verify checks live in `skills/SKILL.md`.
This skill is the project-level workflow on top of them: it turns a goal into
a plan, and the plan's printed parts are generated by `make.py`.

## Ground rules

1. **Interview, don't assume.** Every number in a plan comes from the user, the
   shop constants, an OpenRocket sim, or a cited source. Anything else is asked.
2. **Prices are never invented.** Each cost is either user-supplied or looked up
   with its vendor, link and date. Unknowns stay `TBD` and the total shows how
   much of it is still unpriced.
3. **Estimates are labelled as estimates** (hours, print time, difficulty), with
   what they're based on.
4. **Owned parts come first.** Check `inventory.yaml` before putting anything
   on the buy list.
5. **One phase at a time.** Finish a phase and get the user's OK before the next
   one, the same way the part library is reviewed step by step.
6. **Safety and legality are gates, not footnotes.** Certification level, club
   or launch site, and the NAR/Tripoli safety codes get checked before money is
   spent.

## Phases

| # | Phase | Output | Gate to next phase |
|---|-------|--------|--------------------|
| 0 | **Goal intake**: target (altitude, motor, cert attempt, competition), budget cap, deadline, launch site/club, experience, tools on hand | `projects/<name>/goal.md` | user confirms the goal |
| 1 | **Feasibility & certification**: motor class vs. current cert level, the club's rail size and waiver altitude, whether the goal fits budget and time | go / no-go plus risks | cert path is clear |
| 2 | **Design**: OpenRocket model, motor choice, stability margin, recovery sizing, per-component **target masses** | `.ork` file + `design.md` | sim meets goal, stability within agreed band |
| 3 | **Bill of materials**: every component tagged `have` / `print` / `buy` / `borrow`, with qty, mass target, and source | `bom.csv` | nothing unaccounted |
| 4 | **Budget**: buy items + consumables (filament g × price, epoxy, motor, ignition) + contingency; total vs. cap | `budget.md` | user approves the spend |
| 5 | **Difficulty & schedule**: per-task difficulty (1–5) and hours, print time, cure times, critical path to the deadline | `schedule.md` | user accepts the timeline |
| 6 | **Parts**: each `print` row → `make.py <part> --param ... ` using the BOM's target mass; must pass `verify.py` | `out/<part>/rev<N>/` | every printed part verified |
| 7 | **Build**: step-by-step assembly, with fits, glue, cure and checkpoints (weigh, CG, swing test as relevant) | `build_log.md` | as-built mass and CG are re-simmed |
| 8 | **Flight prep & post-flight**: preflight checklist, RSO card data, recovery, and a post-flight review fed back into the next rev | `flight_<date>.md` | — |

## Difficulty scale (1–5)

1. Off-the-shelf, glue-and-go
2. Basic tools, simple fits, low-power experience is enough
3. Printed structural parts, epoxy fillets, single-deploy electronics
4. Min-diameter / high-speed, dual deploy, tight tolerances, cert-level motor
5. Composites layup, staging/airstarts, or anything near a waiver limit

Rate each task, and the project overall as its hardest critical task.

## Files

- `inventory.yaml` — what the user already owns (parts, tools, motor hardware, electronics). Updated whenever they acquire or use something.
- `projects/<name>/` — one folder per rocket, holding the phase outputs above.
